Two facts, four states

Today a pin says one thing: has the agent answered? Replies break that, because an answer isn't the end. So a thread keeps track of only two facts: who spoke last, and whether you closed it. Everything you see comes from those two.

The thread card

One card for every state, at the kit's real size. The reply box is always at the bottom, like Figma, Framer and Felt. The check in the header closes the thread; when it's your turn it gets a label so it's easy to find. A new agent message gets a thin blue edge until you've seen it.

Your calls

Who can close a thread?

Only youThe agent replies; you decide it's done. Matches Linear: a person stays responsible, the agent does the work.
The agent too, when it's sureFewer clicks, but a thread could vanish before you've looked at the change.

Where do done threads go?

Off the boardThey live under Done in the list, with a “Show done” switch. Figma does this.
Stay on the board, fadedHistory stays in place, but the board fills up and faded pins already mean “made in another state”.

Show that the agent has seen it?

Not for nowThe agent usually answers in the same turn it reads the comment. A fifth state for a few seconds of value.
Yes, a “looking at it” markLike GitHub's 👀 when Copilot picks up a comment. Worth it if fixes start taking minutes.

What changes underneath

  • A comment gets a list of messages instead of one comment plus one answer. Old notes read as a two-message thread.
  • Status becomes open or done. “Whose turn” isn't stored; it's read from the last message.
  • The agent appends a message instead of resolving. The hook counts threads where you spoke last.
  • “Read” is kept in your browser, so opening a thread never rewrites its file.
  • The agent guide (notes.md) learns the new rule: reply, don't close.

What I looked at

Figma. Check in the header to resolve, unread threads first, resolved ones hidden. Its users keep asking for an in-between state; “whose turn” fills that gap. Forum
Google Docs. Replying to a resolved comment reopens it. Same rule here.
Magnific (Mobbin). A resolved thread's reply box says “Reopen and comment…”, which is where “Reply to reopen…” comes from. Screen
Linear agents. Work is delegated to an agent, but a person stays the owner. Session state comes from the agent's last activity, not a switch. Post
GitHub Copilot. Reacts 👀 when it picks up a comment; follow-up comments on the same PR keep context. Docs
Vercel comments. Agents can list, reply to and resolve toolbar comments from the CLI, with a closing note. Changelog
Framer, Felt, Gamma, Higgsfield (Mobbin). The reply box always sits at the bottom of the card, never behind a “Reply” button.
Your Trove. Nothing on comment threads directly. aicss.dev and the AI-states kits are useful later for the “waiting” animation.
